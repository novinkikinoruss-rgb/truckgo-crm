# TruckGO — CRM логистики

CRM для транспортной компании (перевозка нерудных материалов): клиенты, подрядчики, автопарк, рейсы, взаиморасчёты, карта и ИИ-ассистент. Собрана с нуля: без моковых данных, все цифры (долги, маржа) считаются на лету из реальных рейсов и платежей.

## Структура проекта

```
├── index.html
├── shared/
│   └── types.ts          # единые модели данных (Client, Trip, Payment…) для фронта и бэка
├── server/                # Express-бэкенд
│   ├── index.ts           # точка входа
│   ├── store.ts           # хранилище (JSON-файл data/db.json, переживает перезапуск)
│   ├── routes.ts          # REST CRUD для всех сущностей + /dashboard/summary
│   ├── ai.ts              # интеграция с Claude / Gemini / Perplexity
│   └── telegram.ts        # Telegram-бот водителя
├── src/                   # React-фронтенд
│   ├── main.tsx
│   ├── App.tsx
│   ├── state/AppContext.tsx   # общий стейт: загружает и связывает все сущности
│   ├── lib/                   # api-клиент, форматирование
│   ├── components/
│   │   ├── layout/             # Sidebar, Topbar, мобильная навигация
│   │   ├── ui/                 # переиспользуемые примитивы (Modal, Badge, Input…)
│   │   └── ai/AssistantWidget.tsx

└── data/db.json            # данные CRM (создаётся автоматически, не коммитится)
```

## Как всё связано

Все сущности ссылаются друг на друга по `id`, а не дублируют данные:

- **Рейс (Trip)** ссылается на клиента, подрядчика (если рейс не на своей машине), машину и водителя.
- **Задолженность клиента** = сумма его рейсов − сумма поступивших от него платежей.
- **Задолженность перед подрядчиком** = сумма рейсов, выполненных для него, − сумма выплаченного.
- **Дашборд и раздел «Взаиморасчёты»** ничего не хранят сами — только считают эти формулы по актуальным данным.

Логика расчётов — в одном месте: `shared/types.ts` (`clientDebt`, `contractorDebt`, `tripMargin`).

## Запуск

```bash
npm install
cp .env.example .env   # заполните нужные ключи (необязательно для базовой работы CRM)
npm run dev
```

Откройте http://localhost:3000.

## ИИ-ассистент

Виден в шапке любой страницы. Отвечает **на основе реальных данных вашей CRM** (клиенты, долги, рейсы, автопарк), а не по шаблону. Поддерживает три провайдера — достаточно одного ключа в `.env`:

| Провайдер | Переменная | Где взять |
|---|---|---|
| Claude (Anthropic) | `ANTHROPIC_API_KEY` | console.anthropic.com |
| Google Gemini | `GEMINI_API_KEY` | aistudio.google.com/apikey |
| Perplexity Sonar | `PERPLEXITY_API_KEY` | perplexity.ai/settings/api |

Приоритет: Claude → Gemini → Perplexity. Если ни один ключ не задан, ассистент честно сообщает об этом вместо выдуманного ответа. Статус подключения — в разделе **Настройки**.

## Telegram-бот водителя

Необязателен. Чтобы включить:

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Впишите его в `.env` как `TELEGRAM_BOT_TOKEN` (и `TELEGRAM_BOT_USERNAME`).
3. Укажите `APP_URL` (публичный адрес приложения) — вебхук настроится автоматически при старте, либо вызовите `GET /api/telegram/setup` вручную.
4. В разделе **Автопарк → Водители** укажите `telegramChatId` водителя (он получит его, написав `/start` боту) — тогда бот сможет присылать ему актуальный рейс.

**Токен никогда не хардкодится в коде** — без переменной окружения функции бота просто отключаются с предупреждением в логах.

## Хранение данных

Данные лежат в `data/db.json` (создаётся автоматически). Для продакшена рекомендуется заменить `server/store.ts` на реальную БД (Postgres, Supabase и т.п.) — остальной код (роуты, фронтенд) трогать не придётся, так как все запросы идут через несколько функций (`list`, `get`, `create`, `update`, `remove`) в этом файле.

## Дизайн

Тёмная «диспетчерская» тема вместо типового SaaS: IBM Plex Sans/Mono, янтарный акцент (по аналогии с маячками спецтехники), плотные таблицы, минимум декоративных теней. Все цвета и шрифты — в `src/index.css` (CSS-переменные), их легко поменять под свой бренд.
